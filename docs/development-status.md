## 다음 작업

- [AGENTS.md](../AGENTS.md), 배정 이슈, 연결된 명세·설계만 읽습니다.
- [이슈 지도](issues/issue-map.md)에서 선행 작업을 확인하고 담당 이슈의 완료 기준에 따라 구현합니다. 이슈가 존재하는 것만으로 기능 구현을 시작하지 않습니다.
- 결과를 해당 이슈에 기록하고 [요구사항 추적표](issues/requirement-map.md)와 연결합니다. 중복 생성 전 기존 이슈 번호·범위·관계를 조회합니다.
- [계약과 검증 기록](../contracts/README.md)을 기준으로 #13의 DB 연결·물리 스키마·모의 자료를 구현합니다. #12는 PR #44로 닫혔으며 아직 문자열 OK인 health를 DB 준비 상태와 공통 JSON 응답에 맞춰야 합니다. FE는 [기존 API 차이](../contracts/frontend-handoff.md)를 후속 이관/기능 구현에 적용합니다.
- DB·외부 제공사·실기기·SC 시나리오는 후속 구현 이슈에서 실행하고 증거를 남깁니다. 계약 검증과 빈 Java WAR 빌드는 앱 기능 검증이 아닙니다.
