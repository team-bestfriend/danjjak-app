# 요구사항과 계약 범위

각 동작의 `x-requirements`가 [OpenAPI](openapi.yaml)의 세부 연결입니다. 아래 표는 읽기용 범위 안내이며 [원본 요구사항](../docs/specs/requirements.md)과 [전체 이슈 추적표](../docs/issues/requirement-map.md)의 정의를 대체하지 않습니다.

| 확정 FR | 계약 범위 |
| --- | --- |
| FR-001–004, 053, 057 | 카카오 start/callback, session/logout, users/me, consents/settings |
| FR-005–009, 058 | 은행 목록, 내 계좌·후보·불러오기·기본 계좌, 사람·복수 받는 계좌, 보호자 연락처 |
| FR-010–017 | 7종 템플릿, 패턴 생성·상세·수정·번호 목록·비활성화·실행 시작 |
| FR-018 | FE 현재 대상 강조. 단계 역할은 PatternStep.stepCode에서 제공; 행동 기록에 입력값/좌표를 추가하지 않음 |
| FR-019–026, 054–056 | 실제 START/STEP 안내 대상, 문구·방식 저장, 가족 파일 교체/재생, 현재 문구 TTS |
| FR-027 | FE 번호/정해진 문장 매칭 후 기존 확인창. 서버로 명령 문자열/원음을 보내는 API 없음 |
| FR-028–031, 059 | 송금 최종 제출·숫자/한글 금액·시도 결과 재조회·일괄 확정. 한글 표시는 동일 amount를 사용 |
| FR-032–034 | 잔액/거래 조회, 기록 있는 조회 완료, 고객센터 번호와 전화 선택 완료 |
| FR-035–043 | 동일 서버 FDS 결과, 사유·판정 재조회·재확인·계속/취소·카카오 본인 시연·보호자 번호 |
| FR-044–047 | 동의 기반 실행 시작, 방문 UUID·이전 방문 종료·누적 합계·업무별 최종 확정 |
| FR-048–052 | 기간 집계·단계 후보·결정적 제안 비교·오래된 비교 차단·같은 대상 재녹음 연결 |
| FR-060 | FE 정적 이용방법 설명. 별도 CMS/설명 저장 API 없음 |
| FR-061 | 선택 #35. 사전 생성/캐시 API를 추가하지 않음 |

NFR-004는 실행 가능한 계약과 린트로 검증했습니다. NFR-008은 기존 패키지/mapper 소유권과 필요한 재시도 저장만 정의하는 범위로 검토했습니다. 형식 검사는 데이터 값의 스키마 적합성을 확인하며 실제 서버가 트랜잭션·소유권·동시성 규칙을 지켰다는 증거는 아닙니다.

| SC-016–017 | 불러오기 중복 방지, 복수 계좌 ID·최초 계좌, 임시 선택과 저장 연결 분리 | #19/#21/#28 |
| SC-018 | 숫자/한글 금액, 현재 안내 문구·바이너리 TTS·FE 표현 | #27/#32/#36 |

실제 SC-001–018 실행은 이 이슈에서 하지 않았습니다. 계약 경계값 검사와 실기기/DB/제공사 실행을 구분합니다.
